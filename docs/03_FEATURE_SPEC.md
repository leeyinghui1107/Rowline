# 03 · 功能规格说明书（Feature Spec）

**对象**：WinLinez v1.30（Windows，x86，Win32 + GDI）
**依据**：静态白盒分析（`analysis/`）+ 待补充的黑盒采集（`docs/01`）
**性质**：**行为规格**。中立描述"输入 → 处理 → 输出"，不描述任何原程序实现细节，不含原代码。

## 置信度标记

| 标记 | 含义 |
|---|---|
| ✅ | **已确认**：静态证据充分且多源一致，或已由黑盒交叉验证 |
| 🟡 | **推断**：有明确静态证据指向，但尚未由黑盒验证 |
| ⬜ | **待确认**：仅见痕迹，语义需黑盒用例 `BB-*` 判定 |

### 1.1 系统分解

| ID | 系统 | 职责 | 主要输入 | 主要输出 |

## 2. S1 应用生命周期

| 方面 | 规格 | 置信度 |
|---|---|---|
| **输入** | 进程启动（命令行未使用）；INI 中 8 个设置项 | ✅ |
| **处理** | ① 建立窗口类 ② 创建主窗口 ③ 读取 INI 设置 ④ 载入精灵图集并建立缓存 DC ⑤ 建立调色板 ⑥ 读取高分榜并做完整性校验 ⑦ 以当前时间播种随机源 ⑧ 启动 1 Hz 定时器 ⑨ 进入消息循环 | ✅ |
| **输出** | 主窗口；后台内存 DC；每秒一次的刷新 | ✅ |
| **状态** | 见 §2.1 状态表 | ✅ |

### 2.1 状态机

| 状态 | 进入条件 | 允许动作 | 离开条件 | 可见标志 |
|---|---|---|---|---|
| `ST_INIT` | 进程启动 | — | 窗口类注册完成 | 无窗口 |
| `ST_LOADING` | 窗口已创建 | — | 资源与设置载入完成 | 空白窗口 |
| `ST_READY` | 载入完成 | 选球、移动、菜单 | 首次落子 | 分数已显示 |
| `ST_SELECTED` | 已选中一个球 | 再次点击取消 / 点击目标格移动 | 落子成功或取消 | 该球被标记 |
| `ST_ANIMATING` | 触发消除 | 无输入（消息仍被处理） | 动画结束 | 路径高亮 |
| `ST_RESOLVING` | 动画结束 | 无输入 | 补球完成 | 棋盘重排 |
| `ST_GAMEOVER` | 无可用走法 | 菜单操作 / 重开 | 开始新局 | 结束提示 |
| `ST_TAMPERED` | 高分表校验失败且用户选择重置 | 无（禁用写回） | 退出 | 重置提示弹窗 |

> `ST_TAMPERED` 与 `ST_GAMEOVER` 的相互关系、以及游戏结束弹窗的确切触发点 ⬜（`BB-G14`、`BB-G15`）。

### 2.2 启动时序（已确认步骤）

| 步 | 动作 | 依据 |
|---|---|---|
| 1 | 注册窗口类 `WinLinezWindowClass`，窗口过程位于 `0x402DA2` | ✅ |
| 2 | 类属性：程序图标（资源 ID 3000）、系统箭头光标、黑色背景画刷、菜单资源 1100 | ✅ |
| 3 | 读取 INI：`WindowX`、`WindowY`、`WindowWidth`、`WindowHeight`、`WindowMaximized`、`ShowNext`、`ShowStatistics`、`UseFigures` | ✅ |
| 4 | 载入精灵图集（资源 ID 1111，576×586），建立兼容 DC 并选中该位图 | ✅ |
| 5 | 建立并实现调色板 | ✅ |
| 6 | 读取注册表高分榜；校验不通过则弹窗并按用户选择清表 | ✅ |
| 7 | 计算布局几何（依赖客户区尺寸） | ✅ |
| 8 | 用当前毫秒计数播种随机源 | ✅ |
| 9 | 启动 1 Hz 定时器（ID = 1） | ✅ |

### 2.3 边界条件

| 边界 | 行为 | 置信度 |
|---|---|---|
| 客户区宽/高过小 | 布局公式会出现负数/零；原程序未见显式钳制 | 🟡（建议重构时钳制） |
| INI 缺失 | `GetPrivateProfileIntA` 返回 0 → 窗口位置/尺寸为 0（依赖后续兜底） | 🟡 |
| INI 值非法 | 未见校验 | 🟡 |
| 精灵图集缺失 | 载入失败 → 后续绘制使用空位图 | 🟡 |

## 3. S2 窗口与布局

### 3.1 几何模型

设客户区宽 `W`、高 `H`。公式直接取自 `WM_SIZE`（`0x402EA7` / `0x4036E8`，
两处算术完全一致），并用实机 604×371 校验（docs/11 §5d）：

| 量 | 公式 | 依据 |
|---|---|---|
| 棋盘外框宽 | `327`（0x147，绘制时） / `328`（0x148，居中跨距） | 二进制 |
| 棋盘外框高 | `328`（0x148） | 二进制 |
| 棋盘外框 X | `(W - 328) / 2` | 二进制 `0x40B060`；604 → 138 |
| 棋盘外框 Y | `(H - 376) / 2 + 46` | 二进制 `0x40B064`；371 → 44 |
| 网格内缩 | `2` px | 二进制 `SPRITE_INSET` |
| 格边长 | `36` px | 二进制 + 截图（200% 下格距 76.3 图像像素 ÷ 2.12 = 36 逻辑像素） |
| 左角色 X | `((W - 328) / 2 - 58) / 2` | 二进制 `0x40B088` |
| 右角色 X | `t + 328 + ((t - 58) / 2)`，`t = (W - 328) / 2` | 二进制 `0x40B098` |
| 角色立绘 Y | `(H - 234) / 2 + 100` | 二进制 `0x40B08C - 0x86` |
| 棋盘区宽 | `W - 96`（0x60） | 二进制 `0x40B070` |
| 预览球组 X / Y | `(W - 108) / 2` / `5` | 二进制 `0x40B078` / `0x40B07C` |
| 最小客户区（无裁剪） | `444 × 372` | 由上述公式解出（`layout` 门会断言） |

> **与早期规格的差异**：早期版本把 `[0x40B078] = (W - 0x6C) / 2` 当作棋盘原点 X，
> 又因截图里棋盘居中而改成「垂直居中于 HUD 之下」。现已确认 `0x40B078/7C`
> 是**预览球组**的 X/Y，棋盘原点为 `0x40B060/64`；截图与反汇编并不矛盾。
> 所有除法都是 C 整数除法（向零截断），Rust 的 `/` 语义相同。

### 3.2 规格

| 方面 | 内容 |
|---|---|
| **输入** | 客户区尺寸；`WindowX/Y/Width/Height/Maximized` |
| **处理** | 按上表解算各区域矩形 |
| **输出** | 棋盘原点、侧栏原点、侧栏尺寸 |
| **状态** | 无（每次重算后缓存到全局） |
| **边界** | `W < 328` 时侧栏公式出现负偏移；`H < 234` 时棋盘原 Y 为负 |

## 4. S3 棋盘数据模型

### 4.1 结构

| 项 | 规格 | 置信度 |
|---|---|---|
| 维度 | 9 行 × 9 列 = 81 格 | ✅ |
| 存储 | 连续字节数组，行主序，`index = row * 9 + col` | ✅ |
| 格字节位域 | 低 6 位有效（掩码 `0x3F`）；高 2 位为标记位 | ✅ |
| 颜色编码 | `0` = 空；`1..7` = 七种颜色（精灵集 A）；`8` = 空槽/分隔；`9..15` = 七种多边形（精灵集 B） | 🟡 |
| 辅助数组 | 存在第二组按格索引的字节（偏移 `0x40B2EF`，步长 8）→ 疑似"锁定/已占用"标记 | 🟡 |
| 特殊标记 | 初始化路径中出现 `0x5A` 比较 → 疑似某种不可用格标记 | ⬜ |
| 相邻关系 | 基础偏移表 4 组：左(-1,0)、左上(-1,-1)、上(0,-1)、右上(1,-1)；其余方向由取反/旋转导出 | 🟡 |

### 4.2 规格

| 方面 | 内容 |
|---|---|
| **输入** | 落子（行,列,颜色）、移动（起点→终点）、消除集合 |
| **处理** | 写入格字节（保留高 2 位标记）；空位扫描；邻域查询 |
| **输出** | 更新后的 81 字节数组 |
| **状态** | 棋盘数组；棋盘状态标志字节（3 个，位于棋盘区之前的 `0x40B2E8..EA`） |
| **边界** | 行列索引必须落在 0..8；越界检查在规则函数中成对出现（`<0` 与 `>8`），**双向检查** |

## 16. 已知缺陷与脆弱点（重构时应处理）

| 编号 | 现象 | 依据 | 建议 |
|---|---|---|---|
| D1 | 所有节缺 `IMAGE_SCN_MEM_EXECUTE` | 节表 characteristics 全为 `0xC0000040` | 重构版不继承；现代 Windows 兼容性天然更好 |
