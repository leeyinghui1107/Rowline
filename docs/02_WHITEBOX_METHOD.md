# 02 · 白盒分析要点与伪代码整理方法

> **阅读提示**：第 3 节的分派表现在区分**窗口消息**与**菜单命令 ID**——两者的
> 数值空间恰好重叠（`0x100–0x102` / `0x200–0x202` / `0x300–0x301`）。
> 这是本项目分析过程中最关键的一次纠错，务必先读该节的说明框。

> 目标：把静态分析结论固化成**可复现的、可被第三方复核的分析产物**，而不是一段散乱的反编译文本。
> 本文档描述**方法与要点**；输出的是行为层面的结构描述，不复制原程序代码。

## 1. 白盒工作流

```
① 定位锚点            ② 建立符号          ③ 逐函数解构          ④ 伪代码规范化
   (字符串/IAT 交叉引用)  (重命名 + 结构体)   (职责/输入/输出/副作用)   (统一 DSL 记法)
        ↓                    ↓                      ↓                    ↓
   analysis/xrefs.txt    Ghidra IDB          analysis/funcs/*.md     analysis/pseudo/*.c
```

### 1.1 步骤①：锚点定位（本项目已完成）

| 锚点来源 | 定位手法 | 本项目成果 |
|---|---|---|
| `.data` 字符串 | 对代码段全文搜索字符串 VA 的 32 位立即数 | 52 条常量 → 命中点见 `analysis/xrefs.txt` |
| IAT 槽位 | 解析导入表，得到 `0x4092A0..0x4094A8` 的 API 映射 | 121 个 API；`call [0x409338]` → `GetPixel` |
| 调用目标 | 扫描 `E8 rel32`，取落在代码段内的目标 | ~75 个内部函数候选 |
| 全局变量 | 反向扫描 `0x40Bxxx` 立即数 | 31 个游戏状态全局量 |
| 事件常量 | 扫描 `cmp reg, imm` 二分查找树 | 消息分发表（见 §3.1） |

**可复用脚本**：`tools/xrefs.py`、`tools/global_xref.py`、`tools/disasm.py`（带 IAT/字符串标注）。

### 1.2 步骤②：建立符号（自动化）

`tools/ghidra_post.py` 已内置 **40 个函数名 + 31 个全局名 + 40 个字符串标签 + 2 个结构体**，用 Ghidra headless 执行：

```bash
analyzeHeadless /tmp/ghidra_proj WINLINEZ \
    -import /path/to/WINLINEZ.EXE \
    -postScript ghidra_post.py -scriptPath tools \
    -deleteProject
```

产出：`analysis/pseudo/*.c`（每个锚点函数一份）+ `analysis/pseudo/anchors.json`（地址↔语义映射）。

> 重命名的作用是**让伪代码自解释**。命名依据来自黑盒交叉验证，不来自原程序符号（原程序为 Borland 编译，符号表已被剥离，`.reloc` 为空）。

### 1.3 步骤③：逐函数解构（统一分析卡）

每个函数填一张卡：

```
函数: DrawBoardGrid  @0x401533
职责: 把 81 个棋盘格绘制到客户区
调用: SelectObject / MoveToEx / LineTo / BitBlt
输入: 隐式——全局 g_boardOriginX/Y, g_board[81], g_spriteSetToggle, g_atlasDC
输出: 客户区像素
副作用: 无（纯绘制）
常量: 格边长 36; 边框 0x147 x 0x148; 源图 Y=225; 源图 X = 格值*36 + 集合*288
状态: 无
边界: 格值 0 = 空(不绘制); 格值 8 = 分隔槽; 格值 9..15 = 多边形组
不确定: 源图 X 的 +288 偏移在集合 1 时的确切语义（待 BB-G03 校验）
```

### 1.4 步骤④：伪代码规范化（不复制原码）

反编译器输出受编译器影响大（临时变量名、寄存器分配、控制流形态）。规范化为**行为伪码**，规则：

| 规则 | 说明 |
|---|---|
| R1 去除地址 | 伪码中不出现任何地址、常量表由独立清单引用 |
| R2 具名化 | 临时变量 → 领域名（`tmp1` → `cellColor`, `arr` → `board`） |
| R3 拆分副作用 | `读取`/`写入`/`绘制`/`调用API` 四类逐行标注 |
| R4 边界显式化 | 所有 `cmp` 分支转写为「若 … 则 …（边界条件）」条目 |
| R5 常量外提 | 魔法数替换为 `CONST_` 符号 |
| R6 无原码 | 只写行为，不做逐指令翻译；不可从伪码反推原指令序列 |

**行为伪码记法（本项目统一）**

```
PROC <名称>(输入...) -> 输出
  PRE:  前置条件
  DO:   步骤序列
  INV:  不变量/后置条件
  EDGE: 边界条件与异常分支
```

示例（**原创记法，非原码**）：

```
PROC DrawBoardGrid()
  PRE: g_atlasDC 已选中精灵图集位图
  DO:
    1. 以 1px 灰色画笔绘制棋盘外框的下沉 3D 斜角（327 x 328）
    2. FOR row IN 0..8, FOR col IN 0..8:
         cellValue := g_board[row*9 + col]
         IF cellValue == 0: SKIP            # 空槽不绘制
         srcX := cellValue * 36 + g_spriteSetToggle * 288
         blit(g_atlasDC, srcX, 225, 36, 36) -> 客户区 (originX + 2 + col*36,
                                                          originY + 2 + row*36)
  INV:  绘制后客户区棋盘区与 g_board 完全一致
  EDGE: cellValue > 15 时 srcX 越界（原程序未做检查 → 潜在缺陷）
```

## 2. 关键函数分析要点

### 2.1 渲染循环

| 关注点 | 要点 |
|---|---|
| 入口 | `WndProc_Main` 收 `WM_PAINT` → `BeginPaint` → `SelectPalette`/`RealizePalette` → 调绘制函数 → `EndPaint` |
| 调色板 | 创建 8 位调色板并 `RealizePalette`；**渲染依赖调色板实现**，是跨平台移植的隐藏坑 |
| 绘制顺序 | ① 3D 外框 ② 81 格棋盘 ③ 侧栏背景 ④ 侧栏内容 ⑤ HUD（分数/计数） |
| 双缓冲 | 存在 `CreateCompatibleDC` + `CreateCompatibleBitmap` 对（棋盘缓存与图集缓存），但主绘制直接画到 `BeginPaint` 的 DC（非严格双缓冲） |
| 缩放 | `MulDiv` 出现在导入表，说明存在按比例缩放路径；`LoadImageA` 以 576x586 载入图集，缩放行为需 BB-U03 校验 |
| 复刻风险 | `RealizePalette` + 索引色路径在现代 GPU 合成下色彩会有偏差 → **建议重新设计为 32 位真彩** |

### 2.2 输入处理

| 关注点 | 要点 |
|---|---|
| 消息分发表 | 编译器生成二叉查找树（`cmp ax, imm` 链），**不是** switch 表；重建时按 `ax` 区间归类 |
| 已识别消息 | `0x100` 键按下、`0x101` 字符、`0x102` 左键按下、`0x200` 鼠标移动、`0x202` 左键抬起、`0x300`/`0x301` 自定义消息 |
| 关键缺口 | `WM_COMMAND`（0x111）**不在**主分发表中 → 菜单命令由前置分派器 `0x404F1B` 拦截处理（待确认） |
| 前置分派器 | `WndProc` 首行调用 `0x404F1B`，返回非零即直接返回 → 推测其处理"游戏中"的常规输入 |
| 坐标映射 | `WM_LBUTTONUP` 处理块中可见对棋盘原点的减法与除 36 → 像素坐标→格坐标的映射是 `(px - originX - 2) / 36` 量级，**需 BB-K03 校验取整与越界处理** |
| 双击 | `GetMessageTime` 已导入 → 存在双击判定；需 BB-K04 确认阈值与行为 |
| 捕获 | `SetCapture`/`ReleaseCapture` 已导入 → 存在拖拽语义；需 BB-K05 确认 |
| 悬浮 | `WM_MOUSEMOVE` 处理块中有一个标志位翻转并驱动菜单勾选状态 → 疑似"悬停于某控件"的判定 |

### 2.3 物理 / 碰撞（本作对应"连通判定"）

| 关注点 | 要点 |
|---|---|
| 判定入口 | `Game_EvaluateLine` @0x401CD4：调用棋盘访问器 → 取随机数 → 弹窗 → 重绘若干次（每次之间 `Sleep`）→ 调规则函数 → 更新分数 → 画高亮折线 |
| 规则函数 | `GameRules_ValidateMove` @0x401A4A：先做 **0..8 双向边界检查**（`cmp ecx,8 / test eax,eax; jl / cmp eax,8; jg`），再做 **4 邻域扫描**，命中计数与 **5** 比较 |
| 邻域表 | `0x40A000` 起 4 组 `{dx,dy}` = `(-1,0) (-1,-1) (0,-1) (1,-1)` → **行主序扫描的"已访问邻居"**：左、左上、上、右上 |
| 路径方向 | 其它方向由同一组取反/旋转得到（`0x401698` 中出现 `xor` 组合），**精确的 8 方向顺序需 BB-G04 校验** |
| 格值编码 | 格字节为 6 位有效（`and 0x3F`）→ 低 6 位存颜色/状态，高 2 位存动画/变体标志 |
| 特殊值 | 初始化代码中出现过 `0x5A` 比较 → 可能是"锁定/不可用格"标记，语义待 BB-G03 校验 |
| 消除后 | `Game_EvaluateLine` 尾部调用 `Game_ResetRound`/`Score_UpdateStatus`；补球与下落规则见 §4 的 S6/S7 |
| 复刻风险 | 判定顺序（先左后上 vs 先上后左）会改变**等长路径的选取**，影响动画观感 → **建议重新设计为显式 BFS/A\*，保证确定性** |

### 2.4 存档序列化

| 关注点 | 要点 |
|---|---|
| 配置 | `GetPrivateProfileIntA`（读）/ `WritePrivateProfileStringA`（写）；文件 `WinLinez.INI`；8 个键；读取集中在启动路径，写入集中在退出路径与设置变更处 |
| 高分表 | `RegQueryValueExA`/`RegSetValueExA`，键 `HKCU\SOFTWARE\Ivan Golubev\WinLinez\HighScore` |
| 表结构 | 16 条记录 × 32 字节；`name` 在 +0（≤28 字节，NUL 填充），`score` 在 +0x1C（u32）；整体 `REG_BINARY` 512 字节 |
| 校验 | 另存 `Hash` = 16 字节 `REG_BINARY` = 4×u32，由 `Hash_Compute` 对 512 字节表计算后，逐项 XOR 4 个固定掩码得到 |
| 掩码 | `0x34A09D43`、`0x7A23DE01`、`0x147341EF`、`0xF7D38E01` |
| 校验失败 | 弹 `MessageBoxA(YESNO|WARNING)`；选"是"→ 清空表并**禁止后续写回**；选"否"→ 保留并正常写回 |
| 默认值 | 清表后：记录 0 分数 = 100，记录 1..15 分数 = 0，姓名填入预置串 |
| 复刻风险 | 哈希算法（`Hash_Compute` 内部为分块迭代 + `0x407455`/`0x4074E4`）实现细节复杂，**且属于"技术保护措施"的反面**（防作弊）→ **建议重新设计为可解释的校验（如明文记录 + 版本号），不复制原掩码与算法** |

## 3. 消息分发表重建

### 3.1 已识别分派（主窗口）

> ⚠️ **重要陷阱**：本程序的菜单命令 ID 恰好落在 `0x100–0x102` / `0x200–0x202` / `0x300–0x301`，
> 与 Windows 消息常量 `WM_KEYDOWN`/`WM_MOUSEMOVE`/`WM_APP` **数值完全重叠**。
> 仅看 `cmp ax, 0x200` 无法判断是在比消息还是在比命令 ID。
> **判定规则**：比较 `msg` 寄存器 → 消息；比较 `LOWORD(wParam)` → 菜单命令 ID。
> 本项目早期分析曾因此把命令分派误读为消息分派，此处已更正。

**（a）窗口消息分派树** — `0x403B65`，比较 `edi = msg`：

| 消息 | 值 | 处理块 | 行为摘要 |
|---|---|---|---|
| WM_CREATE | 0x01 | 0x402DF1 | 载入精灵图集、建立 DC、读高分表、建调色板、启动 1 Hz 定时器、计算布局 |
| WM_DESTROY | 0x02 | 0x403BF0 | 退出清理 |
| WM_SIZE | 0x05 | 0x403BC4 | 重算布局几何 |
| WM_PAINT | 0x0F | 0x402FA0 | `BeginPaint` → 调色板 → 绘制 → `EndPaint` |
| WM_CLOSE | 0x10 | 0x403BDA | 关闭窗口 |
| WM_GETFONT | 0x24 | 0x4036D5 | 返回控件字体 |
| **WM_COMMAND** | 0x111 | **0x40366D** | 转入菜单命令分派树 |
| WM_TIMER | 0x113 | 0x403369 | 周期刷新侧栏/预览 |
| WM_MOUSEMOVE | 0x201 | 0x40305E | 更新悬停 |
| WM_LBUTTONDOWN | 0x202 | 0x40308E | 选球 / 落子 |
| 自定义消息 | 0x900 | 0x4033DD | 高分与结束流程（分数比较 + `MessageBoxA`） |

**（c）菜单树**（`RT_MENU` / `MENUITEMTEMPLATE`，Borland 变体，已精确解析 276/276 字节）

```
文件(&F)                        [POPUP]
  新建(&N)        F4            id=256
  显示高分榜(&H)                 id=257
  退出(&X)        Alt-F9        id=258
选项(&O)                        [POPUP]
  下一组(&N)      F3            id=512   -> INI ShowNext
  显示统计(&S)    F5            id=513   -> INI ShowStatistics
  使用形状        F6            id=514   -> INI UseFigures
  帮助(&H)                      id=16528
  内容(&C)        F1            id=768
  关于(&A)...                   id=769
```

> **交叉校验**：解析器要求 **① 精确消费 276 字节** 且 **② 全部 6 个加速键 ID 都能在菜单中找到对应项**，
> 两条同时成立才判定格式正确。实现见 `tools/menu_parser.py`。
>
> **附带发现**：菜单文本中的 `Alt-X` 只是显示提示，实际注册的加速键是 `Alt+F9`（ID 258）——两者不一致，属原作瑕疵。
>
> **国际化影响**：菜单是**简体中文**，说明这是 Ivan Golubev 原作的**中文本地化发行版**；
> 俄罗斯语提示串（高分表被篡改等）仍保留在二进制中。重构版应做完整 i18n。


### 3.2 伪代码整理方法

1. **先建表，再写码**：把分派关系抽成表（本文档 §3.1），避免在伪码里丢消息。
2. **每个处理块写一张卡**：触发条件 / 副作用 / 恒等式 / 边界。
3. **对照黑盒**：每条分派都要在 `docs/01` 找到对应用例编号；找不到的标 `待验证`。
4. **伪码只写一次**：定稿后冻结，变更走修订记录，避免出现"两份伪码互相矛盾"。

## 4. 逻辑还原优先级

| 优先级 | 函数 | 理由 | 预计难度 |
|---|---|---|---|
| P0 | `GameRules_ValidateMove` (0x401A4A) | 规则核心，决定游戏是否"手感一致" | 高 |
| P0 | `DrawBoardGrid` (0x401533) | 已有充分静态结论，动态校验即可 | 低 |
| P0 | `ScoreTable_Load/Save` (0x402A50/0x402BFD) | 格式已完全确定 | 低 |
| P1 | `Game_EvaluateLine` (0x401CD4) | 消除流程与动画编排 | 中高 |
| P1 | `Board_InitNewGame` (0x401743) | 初始局面生成 | 中 |
| P1 | `MenuCommandRouter` (0x4019FF) + `MenuAction_Dispatch` (0x402134) | 菜单语义映射 | 中 |
| P2 | `DrawPanel_*` (0x401EC6/0x40238B/0x4024E7/0x402680) | 侧栏与 HUD | 低 |
| P2 | `Hash_Compute` (0x4029C3) | **建议不复刻**，只还原其"存在性与触发条件" | 中 |
| P3 | `Paint_CustomControl` (0x407099) 等 X* 控件 | 与游戏玩法无关，可整体重写 | 中 |
