# 01 · 黑盒行为采集方案与记录模板

> 目的：在**不阅读实现**的前提下，把可执行文件对外表现出来的全部可观测行为，采集成可复现、可判定的结构化记录。
> 白盒结论只用于**校验**采集结果，不用于替代采集。
> 本文档不包含任何原程序代码。

## 0. 工具化（已实现，优先使用脚本而非人工）

> 完整操作手册见 **[tools/blackbox/README.md](../tools/blackbox/README.md)**。
> 本文档定义**采什么**；工具决定**怎么采**。

| 工具 | 作用 | 关闭的采集项 | 平台 |
|---|---|---|---|
| `tools/blackbox/winprobe.c` | 运行时采集：窗口/控件树、**运行时菜单树**（含勾选态）、INI 原始字节、注册表原始字节、屏幕与客户区尺寸 | BB-M01/02、BB-U01、BB-N08 | Windows |
| `tools/blackbox/geometry.py` | 从截图**测量**棋盘原点、格边长、网格边数、外框矩形、精灵内边距 | BB-U02/04、BB-N01 | 任意 |
| `tools/blackbox/analyze.py` | 把测量结果与 `docs/03` 规格逐条比对，产出一致性报告 | 自动校验 | 任意 |
| `tools/blackbox/simulate.py` | 生成模拟窗口图（用原图集作渲染夹具），给测量工具做回归 | 回归夹具 | 任意 |
| `tools/blackbox/inputlog.py` | 录制键鼠事件到 CSV（F8 打标记分段） | BB-K* 复现 | Windows |
| `tools/blackbox/inputlog_ahk.ahk` | 同上，AutoHotkey 版 | BB-K* 复现 | Windows |
| `tools/blackbox/checklist.py` | 54 项采集清单的状态/证据/笔记管理 + 一致性自检 + Markdown 进度导出 | 全局 | 任意 |
| `tools/blackbox/pngio.py` | 零依赖 PNG 读写（8 位 RGB/RGBA/调色板） | 底座 | 任意 |

**典型流程**

```bash
# 1) 运行时快照（信息密度最高，一次关闭 6+ 项）
winprobe.exe --out bb/run1 --class WinLinezWindowClass
python tools/blackbox/analyze.py probe bb/run1 --out bb/run1

# 2) 截图几何
python tools/blackbox/analyze.py shot bb/shots/board.png --out bb/run1

# 3) 回填清单（带证据）
python tools/blackbox/checklist.py set BB-U04 --status done \
    --evidence bb/run1/geometry.json --note "实测原点与公式一致"
python tools/blackbox/checklist.py summary
```

**测量工具的可靠性**：`geometry.py` 不依赖规格公式（先检测棋盘外框得绝对原点，
再用"饱和像素落入 9×9 槽位"验证），因此能反过来证伪公式。
已在 8 组尺寸 × 2 种精灵集上回归，期望值 100% 命中。

## 1. 采集前的准备

### 1.1 环境矩阵

| 变量 | 取值 | 理由 |
|---|---|---|
| 操作系统 | Windows 98 SE / XP SP3 / 10 | 原程序为 1999 年 Borland 产物，无 ASLR/DEP；现代 Windows 可能因节缺 EXECUTE 标志而无法执行，XP 快照为兜底 |
| 显示 | 1024×768 × 32 位色 | 与原生 GDI 8 位调色板路径一致；另测 640×480 与 1920×1080 观察布局响应 |
| DPI | 100%（系统默认） | 程序无 DPI 感知清单，避免引入额外变量 |
| 区域设置 | 俄语（ru-RU）+ CP1251 代码页 | 原程序内置俄文提示串；英/美区域设置下会显示乱码，需在报告中注明 |
| 网络 | **关闭** | 无网络功能；避免 1999 年程序意外外联 |
| 快照 | 采集前建基线快照 | 每个用例可一键回滚 |

### 1.2 工具清单

| 工具 | 用途 | 备注 |
|---|---|---|
| ProcMon | 文件/注册表 I/O 全量追踪 | 导出 PML → CSV，用于生成存档格式断言 |
| x64dbg | 动态断点 | 仅用于**验证**白盒假设（如 `SetPixel` 坐标序列），不作为主要采集手段 |
| WinSpy / Spy++ | 窗口/控件树枚举 | 采集 UI 布局的唯一可靠来源 |
| 录屏（OBS / Camtasia） | 行为基线 | 30/60 fps，带时间戳 |
| AutoHotkey / 按键记录器 | 输入序列回放 | 录制 → 回放，保证用例可重放 |
| 资源监视器 | 文件尺寸变化 | 验证 INI 写入时机 |
| RegShot / reg export | 注册表快照 | 验证高分表写入 |

## 2. 需录制的行为清单

### 2.1 菜单流程

| 编号 | 行为 | 采集方法 | 通过判据 |
|---|---|---|---|
| BB-M01 | 启动后主菜单完整项与层级 | 录屏 + 资源导出（`MENU/1100`） | 逐项截图；记录每个项的 Accelerator 提示文本 |
| BB-M02 | 每个菜单项的 Enabled/Checked 初始态 | WinSpy + 逐项悬停录屏 | 记录哪些项带勾选标记（`MF_CHECKED`） |
| BB-M03 | 菜单项点击后的行为 | 逐项点击录屏 | 每个菜单项记录：是否弹窗、是否改变棋盘、是否改变配置 |
| BB-M04 | 子菜单展开延迟与层级 | 录屏帧率分析 | 记录展开延迟 ms |
| BB-M05 | 菜单与快捷键的等价性 | 分别用鼠标和快捷键触发同一功能 | 两者行为必须一致 |
| BB-M06 | 菜单项在游戏进行中 vs 结束后是否可用 | 两轮各测一遍 | 记录差异（部分项被禁用） |

### 2.2 按键 / 鼠标映射

| 编号 | 行为 | 采集方法 | 通过判据 |
|---|---|---|---|
| BB-K01 | 全部快捷键及其作用 | 对 F1–F12、Alt+字母、Ctrl+字母 逐个按压录屏 | 建立 `按键 → 功能` 映射表 |
| BB-K02 | 快捷键在不同窗口焦点下是否生效 | 主窗口 / 对话框 / 统计窗口分别测 | 记录差异 |
| BB-K03 | 鼠标单击棋盘格的效果 | 逐格点击录屏 | 记录选中/移动/落子的视觉反馈 |
| BB-K04 | 双击行为 | 对同一格快速双击 | 记录是否与两次单击不同 |
| BB-K05 | 拖拽行为 | 按下-移动-抬起全程录屏 | 记录是否支持拖拽 |
| BB-K06 | 鼠标悬停效果 | 缓慢划过棋盘录屏 | 记录悬停高亮规则 |
| BB-K07 | 右键 / 中键行为 | 分别点击 | 记录是否有上下文菜单 |
| BB-K08 | 鼠标移出窗口 | 移出后再移入 | 记录状态复位规则 |
| BB-K09 | 窗口缩放中的输入 | 拖拽窗口边框同时点击棋盘 | 记录坐标映射是否随尺寸变化 |
| BB-K10 | 键盘方向键 / 回车的棋盘交互 | 逐键按压 | 记录是否存在键盘操控 |

### 2.3 游戏规则

| 编号 | 行为 | 采集方法 | 通过判据 |
|---|---|---|---|
| BB-G01 | 新局初始棋盘内容 | 每局截图 + 逐格记录球色 | 记录初始球数、颜色分布、是否随机 |
| BB-G02 | 一次有效操作后棋盘如何变化 | 逐次操作录屏 | 记录新球从何处生成、落点规则 |
| BB-G03 | 消除触发条件 | 构造 3 连 / 4 连 / 5 连 / 6 连 | 记录最小消除数量（白盒提示为 5，需实测） |
| BB-G04 | 连线是否允许拐弯 | 构造 L 形、U 形路径 | 记录拐弯次数上限与折线规则 |
| BB-G05 | 连线是否允许穿越已有球 | 构造被阻挡路径 | 记录阻挡规则 |
| BB-G06 | 消除后棋盘如何重排 | 消除前后逐帧比对 | 记录是否下落、是否补充新球、补充时机 |
| BB-G07 | 棋盘满时的行为 | 持续操作直到无路可走 | 记录结束条件与提示 |
| BB-G08 | 无可消除连线时的棋盘演化 | 长时录制 | 记录是否随机补充球、何时补充 |

| BB-G13 | 等级/关卡推进 | 连续多局 | 记录分数或局数触发的条件与变化 |
| BB-G14 | 游戏结束条件与结束画面 | 走到结束 | 记录结束判定、弹窗文案、按钮 |
| BB-G15 | 新纪录判定 | 刻意超过历史最高分 | 记录提示弹窗与按钮行为 |

## 4. 采集执行顺序（优先级）

| 优先级 | 批次 | 内容 | 理由 |
|---|---|---|---|
| P0 | 批次 A | BB-U01..U12（UI 布局）、BB-M01..M06（菜单） | 成本最低、信息密度最高；布局与菜单是重构的骨架 |
| P0 | 批次 B | BB-N01..N05、BB-K01..K10 | 数值与输入是规则建模的输入 |
| P1 | 批次 C | BB-G01..G15（规则） | 最耗时；需大量构造用例 |
| P1 | 批次 D | BB-N06..N11（数值表） | 依赖批次 C 的场景 |
| P2 | 批次 E | 存档差分、主题、边界条件 | 用于回归验证 |

## 5. 采集完成度自检

- [ ] 每个用例卡都有证据附件（录屏时间码 / 截图 / 日志）
- [ ] 每个数值都有 **≥5 次独立观测**或标注为"单次观测，低置信"
- [ ] 规则类用例覆盖边界：最小阈值、阈值±1、棋盘满、不可达、单色满盘
- [ ] UI 布局在 **≥3 种窗口尺寸**下采集
- [ ] 俄语弹窗文本已用正确代码页转写并归档
- [ ] 全部数值表已填入 §3.2 模板，并与 §3.3 白盒推断列对照
- [ ] 差异项已全部标注处置（一致 / 需修正 / 标记为待定）
- [ ] `python tools/blackbox/checklist.py check` 通过（每个 done 项都有证据）
- [ ] 机器可判定项已用 `analyze.py` 产出**一致性报告**并随证据归档
